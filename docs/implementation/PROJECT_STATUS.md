## Known limits and defects (honest list)

1. **Incremental re-index is not faster on database-bound workloads.** It saves parsing but still reads and hashes every file, copies unchanged rows into the new generation, and deletes the old one. Measured on a 3,000-file synthetic repo, an unchanged re-index (12.2 s) was *slower* than the first index (7.5 s). Moving rows instead of copying them would fix this but conflicts with atomic publish; deferred.
2. **Import resolution is conventional, not compiler-accurate.** No `tsconfig`/bundler path aliases (reported `unsupported`), no dynamic imports/`require` with non-literals, no Python namespace-package or `sys.path` manipulation, no `__init__` re-export chasing, no monorepo package linking beyond declared names.
3. **No references, type resolution, or `IMPLEMENTS` edges** — reported as unsupported, never guessed. `EXTENDS_SYMBOL` is inferred only for same-file or directly-imported base names. **Calls (Phase 03) are name-based and inferred**: recall is limited (method calls on non-`self` receivers, higher-order calls, decorators, dynamic dispatch and re-export chains are unresolved), and a `CALLS` edge is evidence of a probable call, not of execution. Ambiguous names produce `ambiguous` edges to each candidate rather than a guess.
4. **Symbol IDs change** on rename/move or reordering among same-named siblings; **file IDs change every generation** (links to a file 404 after a re-index; the UI says so).
5. **Freshness is a metadata estimate** (size + mtime) computed by walking the tree on each request (~0.45 s at 3,000 files); it can miss same-size edits within one mtime tick and may count files the indexer would skip.
6. **Search is substring matching (the originally planned Phase 03 hybrid/semantic search was not built and is unscheduled) with simple ranking** (no fuzzy/semantic ranking, no stemming); a `LIKE '%q%'` scan costs ~170 ms average at 36,000 symbols. Phase 03 owns real search.
7. Indexing runs in an in-process background task, not a durable queue; a killed backend leaves a `running` snapshot until the next start recovers it.
8. A tree-sitter crash in native code would terminate the backend process (no sandboxing); see the threat model.
9. Diagnostics are capped (default 500 per run) and sorted warnings-first; truncation is reported as a run warning.
10. The Phase 01 `FileOut.language` for `.tsx`/`.jsx` changed from "TypeScript"/"JavaScript" to "TSX"/"JSX" (Phase 02 design decision); skip-count keys changed to upper-case codes. Clients of the Phase 01 API must adapt (the bundled UI does).
11. `scripts/*.ps1` were authored but never executed; the shell equivalents are what was run.
12. **Phase 03 — Python is parsed with tree-sitter, not `ast`** (deliberate; see `CODE_INTELLIGENCE_GRAPH.md`). The file-level graph, cycles and depth use `IMPORTS_FILE` only. Impact and cycle endpoints recompute per request (no cache): traversal is capped at 5,000 nodes / depth 10 and cycle analysis at 500,000 edges, with `truncated` flags when hit.
13. **Phase 03 — `REFERENCES` is not provided** (not genuinely extractable without scope/type resolution). `DEFINES` is derived from symbol parents rather than stored.
14. **Phase 03 — static type checking:** `mypy` (2.4.0) crashes with an internal error when its cache lives on the Windows mount; with `--cache-dir` elsewhere it runs and reports 13 errors in five Phase 01 files (`core/config.py`, `core/logging.py`, `main.py`, `planner.py`, `api/tasks.py`), none in Phase 02/03 modules. mypy is not part of the project gates.
15. **Phase 03 — incremental re-index still re-reads and re-copies every file** (limit 1 unchanged). Idempotence and correctness are tested; speed is not improved.

16. **Phase 04 — Python only.** JavaScript/TypeScript and other languages are indexed but have no rules. The API reports this.
17. **Phase 04 — pattern rules, not proofs.** No data-flow analysis: `eval`, shell, deserialization and credential rules flag constructs, so false positives (trusted input, fixtures) and false negatives (aliases, runtime-built code) exist. Per-rule limitations are in `STATIC_ANALYSIS.md` and in every finding.
18. **Phase 04 — in-process execution.** Runs execute in an API background task: no queue, no cancellation, no resume (an interrupted run is marked failed at startup). Analysis reads the published index generation, so unindexed edits are not seen; incremental runs still read and hash every file.
19. **Phase 04 — configuration is read-only through the API and inline `# nova: ignore` comments are not supported**; suppression is per finding, with a reason, via `PATCH`.
20. **Phase 04 — fingerprints** survive moved code but not renames of the file or enclosing function; adding an identical construct earlier in the same scope shifts later ordinals.
21. **Phase 06 — heuristic, not diagnosis.** Rankings come from stack frames, the static call graph, findings and measured coverage; runtime values are not in a traceback, so every root cause stays a hypothesis. Python/pytest only; no git blame; no AI provider.
22. **Phase 06 — fingerprints** ignore line numbers: moved code does not split a failure, but two failures in one function with the same message and test merge; renames split them.
23. **Phase 06 — verification** reruns repository test code in the Phase 05 restricted subprocess (not a sandbox); `NOT_REPRODUCED_IN_VERIFICATION_RUN` is not proof of a fix. Not verified on Windows or in a real browser.
24. **Phase 07 — local Git only.** No hosted pull requests; untracked files are reported, not analysed; signatures and stable symbol ids are Python-only (other languages use the index only when it is current).
25. **Phase 07 — risk weights are documented judgement, not calibrated**, and the score is a ranking aid, not a defect probability. `test_results` is always unavailable because reviews never run tests; `coverage` is usually unavailable.
26. **Phase 07 — impact and test linkage are structural.** "Potentially affected" tests import a changed file; no claim of exercise without coverage evidence. REV-DEL-001 needs an index built before the deletion; REV-TEST-001 needs test discovery.
27. **Phase 07 — reviews run in an in-process background task** (lost on restart; at most 3 active). No AI provider. Not verified on Windows or in a real browser.

28. **Phase 08 — three automatic fixes only** (`== None`, mutable default argument, unused import), LF files with a final newline; everything else needs a manual diff or is diagnostic-only. No AI provider.
29. **Phase 08 — recovery is guidance, not an endpoint.** The reverse diff and steps are returned; NOVA does not roll back for you. A narrow race remains between the final staleness check and the file replace.
30. **Phase 08 — verification is not a sandbox** (Phase 05 restricted subprocess; Python/pytest only). `PASSED` means the selected checks passed, not that the change is correct. Ranking weights are documented judgement, not calibrated. Verification runs in an in-process background task (a restart leaves it `PENDING`). Not verified on Windows or in a real browser.
31. **Phase 11 — live GitHub is unverified.** The adapter, webhook receiver and status reporting were exercised only through a mocked transport; the GitHub Actions workflow (`.github/workflows/ci.yml`) has not run on GitHub and references actions by major tag, not commit SHA. No other providers. No background scheduler for status-report retries.
32. **Phase 11 — verification is bound to the checked-out revision** (Phase 10 rule). Pull-request code is never executed by a webhook; readiness never includes security, migration or deployment evidence (the latter two can be required by policy and then produce BLOCKED).
33. **Phase 12 — live OSV is unverified.** Advisory matching was verified with offline OSV-format fixtures and a mocked transport. Code rules cover Python only; taint tracking is intraprocedural; only PyPI and npm manifests are inventoried (yarn/pnpm lockfiles, Pipfile, setup.py, go.mod and others are reported as gaps); lockfiles are never edited; secret detection is best-effort and not exhaustive; no SBOM export, container or IaC scanning. The security readiness rule is opt-in (`require_security_scan`).
34. **Phase 13 — telemetry is in memory.** Metrics, spans, recent logs and SLO history are lost on restart and are per process. Alerts are evaluated on request (periodic evaluation is opt-in). OTLP export and email delivery are not implemented; signed webhook and Slack-compatible delivery were verified only through an injected transport. Memory is not measurable without psutil, `/proc` or `resource` (e.g. plain Windows). The operational readiness rule is opt-in (`require_operational_health`).
35. **Phase 14 — performance evidence is local and synthetic.** Timings come from one noisy 2-CPU sandbox on generated fixtures (3–5 repeats); baselines in `backend/benchmarks/baseline.json` are valid only for comparable hardware (otherwise `environment_mismatch`). Only SQLite was measured. No application cache, priority queue, memory-aware admission, running-job cancellation or list virtualization was added (no measured need / not implemented). Jobs still run in-process with cooperative time budgets and no hard CPU/memory isolation. Bundle sizes are build outputs, not browser load-time measurements.
37. **Phase 16 — nothing was verified against a real provider.** All HTTP in tests is mocked; GitHub / tracker behaviour against live accounts, PostgreSQL, multi-process workers and a real browser are unverified. Credential encryption is application-level with an environment-supplied key, not a KMS/HSM. Outbound delivery is at-least-once. No retention purge job ships (the window is documented only), inbound rate limiting is per process, PR webhooks are not turned into change requests, and loading third-party extension code is deferred. See docs/architecture/INTEGRATIONS.md.
36. **Phase 15 — no scheduler, notifications, SSO/OIDC or organization-creation API.** Nothing escalates, expires or is marked overdue (`overdue` is always `null`); the queue is pull-based. Audit tables are append-only through SQLite triggers, which anyone with file write access can remove — they are not cryptographically immutable and PostgreSQL equivalents are not implemented. Evidence labels are attestations and cannot satisfy verification policies. Unowned repositories stay workspace-visible. Concurrency was tested with threads in one SQLite process; the UI was tested in jsdom, not a real browser.

38. **Phase 18 — release decision is NOT RELEASE READY.** See `docs/acceptance/RELEASE_CERTIFICATION.md`, `docs/acceptance/DEFECT_REGISTER.md` and `docs/operations/RELEASE_READINESS_REPORT.md` for the blockers and the work needed before reassessment (version control and traceable artifacts, container/CI execution, separate-hardware restore drill, real-browser and accessibility pass, one real provider, open Medium findings F-003/F-005/F-007/F-011/F-012).
